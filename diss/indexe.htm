Hybrid method for smart contract security auditing based on static analysis and fuzzing with detection completeness evaluation

Author: Lukyanenko Alla Andreevna

Supervisor: Kharchenko Anna Vladimirovna, Candidate of Pedagogical Sciences, Associate Professor

Annotation

The work contains 55 pages, 18 figures, 15 sources.

Keywords: SMART CONTRACTS, BLOCKCHAIN, DIGITAL ASSETS, TOKENIZATION, WEB DEVELOPMENT, HTML, CSS, JAVASCRIPT, REACT, SOLIDITY, HARDHAT, ETHERS.JS, OPENZEPPELIN, METAMASK.

The aim of the work is to develop a smart contract for digital asset management and a web application for interacting with this contract, ultimately creating a full-fledged decentralized system (dApp) that allows users to connect a wallet, view their balance and transfer tokens, and administrators to issue new tokens and suspend contract operations. The main functionality is ERC-20 token management with extended security mechanisms [9], [11].

In preparation for the work, the basic concepts of blockchain technologies and smart contracts, the principles of developing decentralized applications, the fundamentals of web frameworks for building user interfaces [4], [5], the design of cryptographic wallets (MetaMask), and smart contract development environments [10], [12] were studied.

Introduction

Smart contracts and blockchain technology represent one of the most promising areas in digital finance and decentralized applications. The work is aimed at studying the design and testing of smart contracts for digital asset management in a decentralized environment.

The relevance of the work is explained by the fact that more and more companies and individuals are switching to digital financial assets [8], while there are few high-quality, secure and verified solutions for their issuance and management: smart contract development has its own specifics, and it is often difficult to compose a correct contract that supports all the necessary security and management functions.

Object of research: a smart contract in a blockchain network.

Subject of research: an ERC-20 standard smart contract for digital asset management.

To achieve the aim, the following tasks were defined:

  • study the structure and operating principles of smart contracts in general;
  • consider the specifics of the ERC-20 standard and extended security mechanisms;
  • develop a smart contract with issuance, transfer, burning and pausing functions;
  • implement a web application with a convenient interface for interacting with the contract;
  • add the ability to connect a wallet (MetaMask);
  • implement balance viewing and token transfers between addresses;
  • add an admin panel for issuing new tokens and managing the contract state;
  • build a complete working decentralized application based on the above.

Research methods: analysis of scientific and technical literature and blockchain platform documentation, generalization of the collected data, practical programming in Solidity and JavaScript using the Hardhat and React frameworks.

1. Theoretical foundations

The blockchain technology (a distributed database on many nodes of a peer-to-peer network with consensus), the concept and properties of smart contracts (autonomy, determinism, immutability, transparency), their life cycle and the gas mechanism are considered. Token standards ERC-20, ERC-721 and ERC-1155 are analyzed [11]; for digital financial assets the ERC-20 standard is chosen as the best fit for fungible claims. A comparative review of EVM-compatible deployment platforms (Ethereum, Binance Smart Chain, Polygon) is carried out; Ethereum is selected as the target platform.

2. Design and implementation of the smart contract

The choice of tools is substantiated: the Solidity 0.8.19 language [10], the Hardhat development environment [12], and the OpenZeppelin Contracts library [9]. The CustomToken smart contract with a modular architecture based on multiple inheritance was developed: ERC20 (basic standard logic), ERC20Burnable (token burning), Pausable (emergency suspension of operations) and AccessControl (role-based model with DEFAULT_ADMIN_ROLE, MINTER_ROLE and PAUSER_ROLE). The key security element is the override of the _update function with the whenNotPaused modifier, which guarantees the suspension of all balance-changing operations.

Unit testing of the contract was carried out using Mocha, Chai and the hardhat-chai-matchers plugin: deployment, transfers, approve/transferFrom, mint, burn, pause/unpause and the role model were verified. All 12 tests passed successfully.

3. Development of the decentralized application

A client-side single-page application (dApp) was designed and implemented in React [5], [6] with the ethers.js library and the MetaMask wallet. The interface includes a navigation bar with wallet connection, balance and token information cards, a token transfer form with validation, and a notification system for transaction statuses. The admin panel is displayed dynamically depending on the roles of the connected user and provides issuance of new tokens (mint) and suspension/resumption of the contract (pause/unpause).

Testing in the local Hardhat network confirmed the full operability of the solution: compilation of 14 Solidity files, contract deployment, execution of transfers, issuance and suspension operations with automatic balance updates.

Conclusion

The main token standards were considered, a comparative analysis of blockchain platforms was carried out, and the CustomToken ERC-20 smart contract with extended security mechanisms (AccessControl, Pausable, Burnable) and a React client web application were designed and developed. The finished software product was successfully tested in the local Hardhat environment. The results obtained form the basis for developing a hybrid method for smart contract security auditing that combines static analysis and fuzzing with an evaluation of detection completeness.

The project code is published on GitHub: github.com/LukyanenkoA/custom-token-project [13].
