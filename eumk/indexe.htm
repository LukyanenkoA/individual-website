Go Development

Electronic educational and methodological complex for the course B1.O.15 “Go Development” for the study program 01.03.02 “Applied Mathematics and Computer Science”. The complex includes a course annotation, the working curriculum, theoretical material (4 lectures) and practical work (4 labs).

About the course

Objective: building theoretical knowledge and practical skills in software development with the Go language, including composite data types, interfaces, concurrency tools and web service development.

Main tasks:

  • master the Go toolchain (go mod, go test, gofmt, go vet);
  • study the language syntax and type system, package organization;
  • master slices, maps, structs and interfaces;
  • master concurrent programming: goroutines, channels, sync, context;
  • learn to build REST APIs with net/http and test applications.

Workload: 2 credit units (72 hours).

Lectures

Lecture 1. Introduction to Go

Section 1 · history and philosophy · toolchain (go mod, gofmt, go vet) · basic syntax

History and application areas of Go. Installing the toolchain, modules and the go run / go build / go test commands. Variables, constants, basic types. Control structures if, for, switch. Functions and multiple return values. Packages and identifier visibility.

📄 Lecture (PDF)

Lecture 2. Composite data types and interfaces

Section 1 · slices, maps, structs · methods · interfaces · error handling

Arrays and slices (len/cap, append). Maps and their specifics. Structs and methods, embedding. Implicit interface implementation, type switch. Error handling: error, errors.Is/As, %w. defer, panic, recover.

📄 Lecture (PDF)

Lecture 3. Concurrent programming

Section 2 · goroutines · channels · select · sync · context

Goroutines and the GMP scheduler. Channels: buffering, direction, closing, range. The select operator. The sync package: WaitGroup, Mutex, Once. context: cancellation and timeouts. Worker pool and pipeline patterns. Data races and the -race flag.

📄 Lecture (PDF)

Lecture 4. Web development and testing in Go

Section 3 · net/http · REST API · JSON · database/sql · go test

HTTP server with net/http, ServeMux, handlers and middleware. REST API and JSON serialization. Working with databases via database/sql. Testing: table-driven tests, t.Run, coverage, the httptest package.

📄 Lecture (PDF)

Practical (laboratory) work

Lab 1. Go basics: programs, functions, packages

Section 1 · go mod · functions · packages · go test

Objective: master the Go toolchain and basic syntax.

Tasks: a CLI converter utility (temperature, currency); moving the logic into a convert package; returning (result, error); table-driven tests; gofmt, go vet, coverage.

📄 Download the work

Lab 2. Slices, maps, structs and interfaces

Section 1 · product catalogue · Store · Repository interface

Objective: master composite data types and interfaces.

Tasks: the Product struct and a map-based store; FilterByCategory and SortByPrice; the Repository interface; ErrNotFound errors and errors.Is; table-driven tests with edge cases.

📄 Download the work

Lab 3. Goroutines and channels

Section 2 · worker pool · WaitGroup · context.WithTimeout

Objective: master concurrent programming.

Tasks: a worker pool with jobs/results channels; synchronization with WaitGroup; a context-based timeout; timing measurements for N = 1, 4, 8; verification with go test -race.

📄 Download the work

Lab 4. REST API in Go

Section 3 · net/http · JSON · middleware · httptest

Objective: develop and test a REST API for a product catalogue.

Tasks: CRUD routes on ServeMux; status codes 201/200/400/404/405; logging middleware; a store with sync.RWMutex; httptest tests with at least 70% coverage.

Course testing

To test knowledge of the course “Go Development”, students are offered a final test. The test includes 10 tasks covering all sections of the course. The result and the grade are displayed immediately after completion — together with explanations for each question.

Testing instructions

Before starting the test, make sure you have a comfortable workplace. Each task is worth 1 point; the point is awarded only for choosing the single correct option. Grading scale: 9–10 — “excellent”, 7–8 — “good”, 5–6 — “satisfactory”, less than 5 — “unsatisfactory”. The result and the grade appear automatically after pressing the “Check” button.
